# M3b guest differential fixture draft

All eight host contract/provenance tests passed again after the required vAPIC-off launcher revision in `artifacts/m3b-safe-gap-host-tests-03/fixtures.log`, within the25-test boundary/fallthrough/control suite. Python AST and all staged JavaScript syntax checks passed in its `report.json`. The earlier `artifacts/m3b-safe-gap-host-tests-01/fixture.log` remains preserved. The separate predecoder passed plain and ASan/UBSan execution in `artifacts/m3b-predecode-tests-02/report.json`, with81,208 checks,3,216 accepted shapes and182 rejected shapes per variant. The first parser compile failure from the default MacOSX27 SDK is preserved at `artifacts/m3b-predecode-tests-01/report.json`. SDK image construction and real guest execution remain unrun. These files are separate from frozen M3a, passive FIFO and timing sources. A staged capture path is present but has not been exercised against a real runtime and requires future real reviewed runtime/image identities. The current M3b runtime still refuses enabled mode until its concrete device-profile guard is established; nothing here bypasses that guard.

The first fixture uses eleven short static programs, a single assembly trampoline and two independent unsigned-arithmetic oracles (guest C and the host contract's reproducible digest). Two generic positive families vary32-/64-bit registers and immediate arithmetic. The remaining small variants cover exactly32 versus33 instructions,128 versus129 owner bytes, an owner ending exactly at a page edge versus crossing it, a memory instruction,64-bit IMUL and a conditional branch consuming entry flags. No workload constants, answers or addresses are admission guards.

Each program warms ordinary A and direct B entries with2048 calls each. The host then resets exact per-PC watches at each gate. Three64-call batches separately exercise the A side exit with no B body, the A-to-B path with varying1..17 iterations, and ordinary direct B entry followed by A continuation. The image and input stream are identical off/on. There are45 gates (one layout plus four per program), each with one COM1 G/K handshake. Gate rows and the final record include deterministic checks/digests. The future host adapter must replay raw serial and gate signals exactly and compare every row with `referenceGates()`, then require pairwise equality for all guest outcomes.

The trampoline saves the C caller stack and callee-saved registers, uses a separate mapped guest stack, seeds every GPR and user RFLAGS, and jumps to the selected A/B entry. The side stub only jumps to the capture routine. Before changing any tested register or flag, that routine records all16 GPRs and the architecturally saved PUSHFQ flags image. PUSHFQ clears VM/RF in that image, so this is not a native RF/VM-state observation. It also compares defined before/after legacy FXSAVE fields for FP/SSE preservation (FCW/FSW/FTW, defined FOP, pointers, MXCSR/mask,80-bit x87 values and all16 XMMs; reserved bytes/bits excluded), then restores the caller. Undefined flag outcomes are never guessed: final CMP0 or SUB1 defines all six arithmetic status flags, while a skipped dynamic-flags body preserves its deliberately seeded complete user flags. Addresses/RSP and opaque FP images are compared within the guest but excluded from the cross-mode digest.

These host checks do not establish selected guest execution. At runtime, positive cases must have selected **fused compiled** entries in each actual measured batch, not activity elsewhere in Linux or merely a byte-prefilter success. Both controls keep M3a enabled with pre-vCPU hotness1500, flags2, normal12000 instance cap and128MiB TB buffer. Exact M3a A/B watches establish the ordinary compiled paths, including the direct B owner; the fused B watch must stay zero. The device profile is fixed pc/acpi-off/hpet-off/usb-off, cpus=maxcpus=1 and512MiB RAM. These are diagnostic correctness settings, not production performance evidence.

The host will watch `[A,A+1)` and `[B,B+1)` before warmup and preserve each stopped raw bank before clearing the watches/ACK. M3b's current source ABI has128 uint32 words, four20-word watches at word32; per-range compiled/TCI entries, B attempts/requests, service paid, accepted predecode, IR rejection, owner publication and clean retry counters. The staged reader validates normalized fields against all raw128 words, exact mode, reserved fields and corresponding lifetime counters; its host corruption tests passed, while real stopped-bank behavior remains to be exercised. All counter overflow/debt errors, wrong profile/PC/generation or running-state reads must fail. An attempted B boundary including a pending-request exit pays one service turn. For positive measured batches, B-attempts must equal all intended B bodies minus the initial ordinary body of each direct-B call. A requested internal B exit materializes EIP=B and resumes through a separate ordinary B owner, so B-attempts minus B-requested counts completed fused bodies, while B-requested counts resumed ordinary bodies. Those two quantities plus the initial direct-B bodies must reconstruct every intended body exactly. The raw requested counts and this source-derived partition are retained; entries themselves are not instruction-retirement counters. The warmed window is retained without asserting an exact tier-specific body partition during initial translation.

The64-bit IMUL, dynamic-entry-flags and exact-page-end side-exit cases deliberately distinguish byte admission from actual IR selection. The byte whitelist admits them. The retained QEMU source lowers64-bit multiply-high to a helper on this backend, dynamic Jcc flags use a compute-flags helper; and an owner ending exactly at the page boundary has its Jcc side target on the next page, so the current unchanged `gen_jmp_rel` emits a lookup/goto-pointer helper. Its owner bytes fit the page and pass predecode, but the actual completed-IR rule rejects helpers and performs one clean ordinary retry. These cases require watched accepted-predecode, IR-rejection and clean-retry evidence during warmup, followed by compiled ordinary correctness and zero fused selection. If actual source lowering differs, the fixture fails for inspection; it does not relabel a predecoder pass as selected fusion or silently weaken the expectation. Memory, oversize and owner-cross-page cases require no admitted predecode/fused owner at A. Exact-page-end is instead an accepted-predecode/clean-IR-retry boundary case; the emitter is not broadened to make this fixture pass. Per-range aggregate rejection counters alone do not identify a particular emitted helper; retain generated IR/source evidence separately when making that causal claim.

The exact side-return state is covered by the guest oracle design. Exact native EIP/lazy flags/full architectural state (including native flag bookkeeping) at **internal B-requested exits and each forced budget return remains open**: this45-gate fixture does not use a stopped native-state hook. A separate256-word hook and11-gate `tests/m3b-boundary` fixture now have passing synthetic host checks, but no real guest observation yet. A final correct checksum is not a substitute. This fixture also does not cover real Asyncify debt rewind, device graph enforcement/DMA, stale owners, eviction, active SMC or instruction faults. Legacy FP/SSE snapshot checks do not claim all extended XSAVE/YMM state.

Before an SDK image build or real guest execution, the owner must review the isolated build and host gate adapter, pin actual source/build/ELF disassembly/image/runtime identities, verify exact static byte/instruction boundaries and the unmodified predecoder against those bytes, and retain the passing host corruption tests for the new contract. The build must be static Linux x86-64, non-PIE with preserved assembly labels,4KiB page alignment and no compiler-generated instructions inside the assembly program extents. Frozen `tests/regions` transport/build infrastructure may be reused by an isolated wrapper without editing it. Real OFF/ON execution and independent replay are required for any correctness claim. Root alone launches them in a later timing gap.

## Staged build and capture entry points (SDK build and guest unrun)

The new `build.py`, `build-provenance.mjs`, `reader.mjs`, `guest.mjs`, `runtime-identity.mjs` and `run.mjs` now stage a bounded first capture. The eight host tests passed; the build and live transport paths still require their first real validation. `test-contract.mjs` contains six synthetic bank/gate/exposure corruption tests, and `test-build-provenance.mjs` contains two exact SDK/compiler-input corruption tests; all eight passed in the retained log above. The guest blocks on a final unacknowledged read after its PASS line, allowing a confirmed final host stop without racing process shutdown; this is not an Asyncify-continuation test.

Root alone may run the pinned Linux SDK image build in an approved execution gap. The host test and future build commands are:

```sh
node --test tests/m3b-fallthrough/test-contract.mjs tests/m3b-fallthrough/test-build-provenance.mjs
python3 scripts/sdk.py python3 tests/m3b-fallthrough/build.py --output artifacts/m3b-fixture-01

The generated shape probe includes the copied header, never a later live include. Compiler, nm and objdump resolved paths, executable hashes, sizes, versions and exact argv are recorded and rechecked; the SDK image digest also covers their dynamic support tools. Its generated native shape probe checks the real ELF bytes against the bounded predecoder, including the32/33-instruction and128/129-byte boundaries. That probe is explicitly host byte-shape evidence, never actual QEMU IR selection or a guest run. The compiler must target Linux x86-64 in `/project` through the exact pinned offline `scripts/sdk.py` invocation; no host substitution is automatic. The builder copies the wrapper’s still-running invocation record into immutable image evidence. The image build alone does not claim the enclosing SDK invocation has finished. All source, tool and copied-input identities are rechecked after construction.
