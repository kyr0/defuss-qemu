# Prospective deadline orchestration v2

This namespace permits an explicitly declared operational deadline for the two remaining requested exploratory repetitions. It does not change the measured work or resume/replace the failed original set. The original finite-v1 sources, first failed campaign, and previously generated10-minute plans02/03 remain immutable.

Only `plan.mjs`, `campaign.mjs`, and `analyze.mjs` are isolated copies. They import the exact frozen finite-v1 horizon, statistics, protocol, snapshot and attempt modules. The campaign still invokes the unchanged finite-v1 runner/browser/adapter/report validator. That runner already accepts deadlines up to1800000ms, starts the same browser guest timer, and applies the existing extra20000ms outer watchdog. No package, runtime byte, guest operation, warmup/batch count, elapsed boundary or statistical margin changes.

`executionPolicy` records the selected600000 or1800000ms deadline,20000ms outer grace, repetition2 or3, exact new plan path and amendment SHA. A prospective amendment must include:

- `schema:1`, `kind:"passive-fifo-finite-deadline-amendment"`, `status:"prospective-declared"`, UTC creation time, unchanged measurement protocol, timeout, grace and `reporting:"all-retained-descriptive-only"`.
- `decision:{source,explicitUserAnswer,timeoutMs}`. `source` is either `explicit-user-answer` with true or `assistant-default-after-unanswered-optional-clarification` with false. Never label an assistant scheduling default as a user answer.
- Exact original plan and repetition declaration `{path,sha256}` references.
- `preservedCampaign:{path,frozenSha256,haltSha256}` binding failed set01. The amendment must postdate its permanent halt and the repetition declaration.
- `retainedPlans` containing the unchanged old02/03 plan paths/hashes and numbers.
- Exactly two `repetitions` numbered2 and3 with distinct new plan/campaign/analysis/review paths, all different from the original declaration's outputs. If either old unexecuted campaign directory exists, fail closed instead of producing extra repetitions.

The plan retains every original input in order and includes every amendment reference. It permits only four-pair exploration, never confirmation. All old numerical rules remain reported for comparison; the uncontrolled host-load caveat prevents causal optimization/deoptimization or confirmation claims. An optional pooled result must include every completed pair with equal pair weighting, remain descriptive, and cannot be called a complete12-pair result because set01 is incomplete.

No actual amendment or plan is generated by tests. After source freeze/review, the execution owner may supply the prospective scheduling declaration and use:

```sh
node benchmarks/harness/passive-fifo-finite-deadline-v2/plan.mjs \
  --control artifacts/passive-fifo-package-off-01 \
  --candidate artifacts/passive-fifo-package-on-01 --kind exploration \
  --amendment artifacts/DECLARED-AMENDMENT.json --repetition 2 --timeout 1800000 \
  --input EACH-ORIGINAL-INPUT-IN-ORDER --input NEW-SOURCE-AND-REVIEW-FREEZES \
  --output benchmarks/plans/DECLARED-NEW-REPEAT02.json
```

The placeholders above are intentionally not runnable. A separate exact command artifact must bind the chosen amendment, all50 original inputs, repetition declaration, and new source/reviewer freeze. The plan writer refuses old or undeclared output paths and writes exclusively, fsyncs the completed plan and its parent directory before success. Campaign/analyzer CLI remains `--plan/--output` and `--campaign/--output` respectively in this namespace. New independent review lives in `experiments/passive-fifo-finite-deadline-review-v2`; it independently replays the same records and validates all amendment references and deadlines.

Host-only tests run via:

```sh
python3 -B experiments/passive-fifo-finite-deadline-review-v2/test-review.py
```

These create synthetic fixtures under project `tmp`; no guest/build/browser is launched. Synthetic10/30-minute four-pair records are cross-checked by JavaScript and Python, but they are not timing evidence. Tests cover deadline/decision typing, preserved evidence and output paths, unchanged numerical endpoint primitives, child deadline mismatch, unknown-attempt rejection, frozen measurement source hashes and acceptance-CLI rejection of test data.
