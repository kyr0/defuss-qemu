# Sustained-v2 generated module input bytes

This is a separate diagnostic wrapper for the frozen `defuss-m2-sustained-v2` workload: five fixed100-call warmup rounds and eight100-call measured rounds per endpoint, in the unchanged balanced order, with all148 gates. The guest bundle, operations, inputs, expected results, runtime WASM, VM settings, and one-time MSG2 off/on choices match the production timing packages. The outer report protocol is `defuss-m2-resource-v2`; both browser and outer report explicitly set `timingEligible:false`. Existing timing loaders reject it.

`observer.js`, `observer.mjs`, and `derive.mjs` are byte-identical to resource-v1. Five exact JavaScript anchors install a shared atomic uint64 bus across the runtime workers. Counters distinguish attempted, compiled, and successfully instantiated modules; record cumulative module input bytes and QEMU uint64 import-vector bytes; and retain maximum module input size. At each stopped warmup/measured boundary, the browser reads a coherent cumulative snapshot and records deltas. Maxima are never subtracted. Overflow, failed/in-flight compilation, changing counters, wrong derivation anchors, or missing stopped-state confirmation fail validation.

The declared descriptive budget is candidate/control cumulative successfully instantiated module input bytes <=1.10, from VM start through the complete stopped gate. Each instantiation counts its bytes again. This does not measure deduplicated code, live functions, native JIT resident bytes, host peak memory, or long-run memory bounds. Passing it does not close those gates or permit product promotion. Instrumentation can affect scheduling and translation admission; every timing from these captures is ineligible for performance conclusions. A single pair supplies descriptive resource evidence only.

The runner requires the exact frozen timing plan. It binds each derived package to the corresponding production manifest, records the plan hash, verifies the stopped12GiB compiler-VM condition before and after capture, and retains host memory observations. A flat project `tmp/s-XXXXXX` directory owns browser scratch. Before/after checks cannot prove that the compiler VM never transiently ran between them; the root scheduler must serialize all owned heavy work. Each run requires a new output/cache; no snapshot restore or observation replacement is supported.

The analyzer replays all guest events against the frozen sustained protocol, compares exact raw serial events including maps, checks all149 COM1 signals, phase chronology, results, phase types/order, and host-condition records. It rehashes production and derived payloads, snapshot, served sources and required input sources, compares complete VM/package specifications, and rejects unrelated observations. Counters include boot and between-phase work in the total; phase sums intentionally exclude those intervals.

Run the diagnostic pair after the uninstrumented timing campaign, while the compiler VM remains stopped. The existing production packages and timing plan are reused; no Bun bundle or runtime rebuild is needed. Run these commands serially from the project root:

```sh
python3 scripts/with-tmp.py node benchmarks/harness/m2-resource-v2/package.mjs --production artifacts/m2-sustained-v2-package-off-01 --output artifacts/m2-resource-v2-package-off-01
python3 scripts/with-tmp.py node benchmarks/harness/m2-resource-v2/package.mjs --production artifacts/m2-sustained-v2-package-on-01 --output artifacts/m2-resource-v2-package-on-01
DEFUSS_VM_CHROME='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' python3 scripts/with-tmp.py node benchmarks/harness/m2-resource-v2/run.mjs --plan artifacts/m2-sustained-v2-exploration-plan-01.json --package artifacts/m2-resource-v2-package-off-01 --output artifacts/m2-resource-v2-off-01
DEFUSS_VM_CHROME='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' python3 scripts/with-tmp.py node benchmarks/harness/m2-resource-v2/run.mjs --plan artifacts/m2-sustained-v2-exploration-plan-01.json --package artifacts/m2-resource-v2-package-on-01 --output artifacts/m2-resource-v2-on-01
python3 scripts/with-tmp.py node benchmarks/harness/m2-resource-v2/analyze.mjs --control artifacts/m2-resource-v2-off-01/report.json --candidate artifacts/m2-resource-v2-on-01/report.json --output artifacts/m2-resource-v2-analysis-01
```

`node --test benchmarks/harness/m2-resource-v2/*.test.mjs` exercises actual tiny WebAssembly compilation through the observer, shared atomic counters, corruption rejection and a complete synthetic148-gate report/pair. These are host-validator tests, not guest execution evidence. Test scratch remains under project `tmp`. Original M1, M2, sustained timing, and resource-v1 sources are unchanged; `provenance.json` records the exact source dependencies.
