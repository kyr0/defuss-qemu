# Bounded M3b shape predecoder

Both plain and ASan/UBSan host runs passed in `artifacts/m3b-predecode-tests-02/report.json`:81,208 checks,3,216 accepted shapes and182 rejected shapes per variant. These are repeated host shape/bounds fixtures, not independent guest observations. The first attempted compilation failed in the host linker while reading the default MacOSX27 SDK TBD architecture; no fixture executable ran. That failed record is retained at `artifacts/m3b-predecode-tests-01/report.json`. No build, guest, QEMU decoder, TCG or generated-code acceptance is implied. Root controls when the host-only tests may run; they must not run during timing collection.

`m3b_predecode(bytes, available, page_remaining, max_insns, &plan)` examines at most the minimum of the supplied accessible byte count, the caller's first-page remainder and128 bytes, and at most the smaller of the original instruction limit and32 instructions. The input is a supplied byte span: no memory callback, second-page lookup or code fetch is available. The caller must establish eligible x86-64/default32 operand decoding, executable ordinary RAM and the current bytes; this parser does not establish mapping permissions, MMIO absence or execution-mode safety.

The admitted shape contains exactly one conditional branch in A, a contiguous B, and one final direct relative JMP whose target is the supplied span's offset zero. The conditional target must equal the byte immediately after that final JMP. A may contain only its conditional branch and B only its closing JMP: the resulting two-instruction shape is admitted without any claim of termination. Relative branches may use signed8-bit or signed32-bit displacements; all16 condition codes are admitted. A side target beyond the supplied bounds, a second conditional branch, an earlier JMP, an unmatched closing edge or a body exceeding a bound rejects the whole shape. Nothing after the successfully closed shape is read or decoded. Side-exit code is not speculatively fetched, including when it lies on the next page.

The whitelist is register/immediate32-/64-bit ADD, OR, AND, SUB, XOR, CMP, TEST, MOV, IMUL, immediate or implicit-one SHL/SHR/SAR, INC/DEC, NOT/NEG and an unprefixed NOP. It covers only explicitly listed encodings. Memory ModRM modes, byte/16-bit operations, ADC/SBB, rotate/variable-count shifts, indirect branches/calls, return/system instructions, unsupported/duplicate prefixes and unknown opcodes reject. One REX is allowed for listed arithmetic/register forms; REX-prefixed branches and NOP reject. Immediate values, register identities, absolute addresses, trip counts and expected answers never gate admission. Generic arbitrary constants and register aliases are fixture data, not optimizer guards.

On success, the caller gets the contiguous per-instruction offset/length/kind/REX records, instruction count and total byte extent; `b_offset`, `jcc_index`, `jcc_target_offset` and `backedge_offset` identify the three boundary positions. The conditional target equals `bytes`, and the last instruction starts at `backedge_offset`. Parsing uses a local plan; normal rejection leaves the complete output zero. A NULL output or overlap between the output object and the bounded input span returns LIMIT without writing. Otherwise the caller must supply valid readable/writable objects. No output pointer is used as scratch for input decoding.

This is an admission prefilter, not an x86 decoder replacement. Frontend integration must independently match actual QEMU decoded emitter, exact instruction length and register-only operands, then reject unsupported effects/helpers/memory operations from the completed IR. It must retain the original instruction metadata, single-owner invalidation and one ordinary clean retry after speculative failure. Those integration and real compiled-path gates are outside these host fixtures.

The host fixture source covers unrelated arithmetic encodings, all branch conditions and short/near combinations, all source/destination register pairs at both widths, negative closure displacements and signed32-bit extrema, the two-instruction branch-only shape, malformed/control/memory/prefix rejection,32-instruction/128-byte boundaries, every truncation of a near-branch shape, inaccessible adjacent pages and output/input overlap. Guard pages test actual bounded host reads; they do not establish guest memory behavior. Plain and ASan/UBSan executions are retained separately in the passed report, with source hashes and all scratch under project `tmp`.
