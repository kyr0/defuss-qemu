# Independent passive-policy outcome review

This Python reviewer audits retained records. It never launches a guest or compiler. It independently checks the new policy's four held-out capture/restore reports, or its separate resource pair and published analysis. It does not turn historical MSG2 data, synthetic fixtures or diagnostic timings into policy evidence.

Both modes bind the frozen validation adapters and their independent review, the exact performance source fingerprint, post-build audit, source overlay, all seven runtime artifacts, package compatibility/payload hashes and recorded host dependencies. The held-out mode recomputes192 cases per run with Python integer xorshift inputs and hashlib SHA256 (384 direct/streamed digests), checks exact raw serial results and lifecycle, effective locked FIFO choice, capture-to-restore report linkage and outer/compressed/inner snapshot digests. The resource mode verifies the same performance WASM, independently reconstructs all five JavaScript observer patches, replays all148 gates/149 signals and maps through the hash-pinned independent sustained protocol reviewer, recomputes every initial/phase/gap/tail counter partition, and checks the declared1.10 byte budget and published analysis. Cumulative maxima are never added or subtracted.

The reusable raw guest protocol dependency is `experiments/m2-sha-msg2/review-sustained-v2.py`, SHA256`b9bd8abf7d9048172e58e7c6f0bf1a1835ed0c5cc2490a5ff015014a63086be8`. Its statistical/MSG2 campaign analysis is not used. No JavaScript analyzer computes the Python audit's expected values; JavaScript fixture construction is used only in host tests.

Run after all actual outputs exist, using fresh review directories:

```sh
python3 -B experiments/passive-fifo-validation-review/review.py heldout --off-capture artifacts/passive-fifo-heldout-off-capture-01/report.json --off-restore artifacts/passive-fifo-heldout-off-restore-01/report.json --on-capture artifacts/passive-fifo-heldout-on-capture-01/report.json --on-restore artifacts/passive-fifo-heldout-on-restore-01/report.json --output artifacts/passive-fifo-heldout-review-01
python3 -B experiments/passive-fifo-validation-review/review.py resources --control artifacts/passive-fifo-resource-off-01/report.json --candidate artifacts/passive-fifo-resource-on-01/report.json --analysis artifacts/passive-fifo-resource-analysis-01/analysis.json --output artifacts/passive-fifo-resource-review-01
```

Every input is hashed again before publishing a successful review. Output directories are never overwritten. A failed audit retains its reason and inventory. The acceptance CLI rejects inputs under project`tmp` and explicitly synthetic records. Direct class calls in tests validate synthetic schemas only; they are not live outcome evidence. Test scratch stays under project`tmp`, with an explicitly named synthetic rejection record retained under`artifacts` to prove the CLI guard.

```sh
python3 -B experiments/passive-fifo-validation-review/test-review.py
```

A passing held-out review establishes those exact digest/state/restore cases. It does not establish that a soft batch occurred or that eviction happened during Asyncify suspension. A passing resource review establishes cumulative module-input accounting, including repeated instantiations. It does not establish native JIT resident bytes, true host peak memory, long-run stability, performance improvement or product promotion.
