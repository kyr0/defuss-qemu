This isolated copy of the frozen independent finite reviewer changes only operational-policy validation, expected deadline/command metadata, and the new orchestration analyzer identity. `policy.py` independently verifies the declaration, original invalid campaign, retained10-minute plans, new repetition paths, original ordered inputs and unchanged measurement/statistical settings. It imports no JavaScript validators.

The exact finite-v1 runner/browser/report/horizon remains in use. Every original H partition,52 phases, raw gate/map/serial/snapshot check, source/build/prerequisite binding, failed/unknown-attempt rule and numerical calculation remains. Confirmation is rejected by the new operational policy. An assistant-selected30-minute default is explicitly distinguished from a user answer. No deadline amendment can rehabilitate failed set01 or permit an unrequested extra repetition.

After a declared future campaign and its JavaScript analysis exist:

```sh
python3 -B experiments/passive-fifo-finite-deadline-review-v2/review.py \
  --campaign artifacts/DECLARED-NEW-REPEAT02 \
  --analysis artifacts/DECLARED-NEW-ANALYSIS02/analysis.json \
  --prerequisites artifacts/passive-fifo-finite-prerequisites-01.json \
  --output artifacts/DECLARED-NEW-INDEPENDENT-REVIEW02
```

Paths are placeholders until the prospective amendment is published. The CLI rejects synthetic/project-tmp evidence and publishes only to a fresh artifact directory with fsync. Successful replay means evidence consistency, not causal improvement, confirmation or product promotion under uncontrolled host load. The original incomplete set and every future result must be reported separately; no best-set selection or missing-pair substitution is permitted.

Run `python3 -B experiments/passive-fifo-finite-deadline-review-v2/test-review.py` for synthetic host tests. The test driver also invokes the four new Node policy tests. All scratch stays under project `tmp`; no VM, browser or build is launched.
